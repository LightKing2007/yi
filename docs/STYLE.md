# 文字规范

## 1 范围

本规范规定“弈”项目中各类文字的写法，适用于：

- 游戏内说明文字：玩法、联机、操作、更新日志、关于等页面；
- 安装程序及下载页面上的说明文字；
- GitHub Release 发布说明；
- 项目文档：README、docs 目录下的文档、CLAUDE.md、PR 模板等。

界面上的按钮、标签及简短提示以简洁为先，不适用第 4.3 条关于完整句子的要求，但术语及标点仍应符合本规范。

## 2 规范性引用文件

下列文件中的内容通过本规范的引用而构成本规范必不可少的条款。

- GB/T 1.1—2020《标准化工作导则 第 1 部分：标准化文件的结构和起草规则》
- GB/T 15834—2011《标点符号用法》
- GB/T 15835—2011《出版物上数字用法》
- ISO/IEC Directives, Part 2, *Principles and rules for the structure and drafting of ISO and IEC documents*
- Semantic Versioning 2.0.0（语义化版本）
- Keep a Changelog 1.1.0

## 3 通用要求

### 3.1 文体

文字应正式、严谨、客观、简明：

- 陈述事实，不使用口语、俚语、网络用语及感叹语气；
- 不夸大，不作无法验证的承诺；
- 同一事物在全文中使用同一名称。

### 3.2 术语

| 术语 | 含义 | 不使用 |
|---|---|---|
| 玩家 | 使用本游戏的人 | 用户、你（发布说明及文档中） |
| 电脑 | 人机对弈中的对手 | AI、机器人 |
| 计算机 | 运行本游戏的设备 | 电脑（指设备时） |
| 对局 | 一盘棋的全过程 | 比赛、游戏（指一盘棋时） |
| 落子 | 在棋盘上放置棋子 | 下子、放子 |
| 安装程序 | 用于安装本游戏的文件 | 安装包（面向玩家的文字中） |
| 下载页面 | http://47.108.181.240:8443/ | 下载站 |
| 段位 | 排位模式的等级，十级至九段 | 等级、分数 |

### 3.3 能愿动词

文档中表示要求的程度时，按 GB/T 1.1—2020 使用下列用语。英文对应 ISO/IEC Directives Part 2 的用语：

| 程度 | 中文 | English |
|---|---|---|
| 要求 | 应、不应 | shall, shall not |
| 推荐 | 宜、不宜 | should, should not |
| 允许 | 可、不必 | may, need not |
| 能力 | 能、不能 | can, cannot |

游戏内说明文字以陈述句描述规则，如“不得”“须”“可”等，不使用“应”“宜”。

## 4 中文

### 4.1 标点符号

标点符号应符合 GB/T 15834—2011：

- 中文语句使用全角标点，不混用半角的逗号、分号、冒号、括号、引号；
- 引号使用“”，引号内再用引号时使用‘’；书名、标准名使用《》；
- 括号使用（），括号内容为整句的补充说明时置于句内；
- 并列的词语之间使用顿号；并列的分句之间使用分号；
- 界面元素名称（按钮、页面）加引号，如“设置”“查看棋局”；
- 游戏内说明的每一段以句号结尾。

### 4.2 数字

数字应符合 GB/T 15835—2011：计量、计数使用阿拉伯数字，如“15 秒”“19 路”“7.5 目”；
约数、定型词语使用汉字，如“一至两次”“十级”“九段”“一键”。

### 4.3 中英文混排

中文与英文单词、阿拉伯数字之间加一个半角空格，如“按 V 键”“macOS 平台”“15 秒”。全角标点前后不加空格。

### 4.4 更新日志

更新日志即游戏内“更多”中的“日志”页面（`src/ui/info.ts` 的 `LOG`），每个版本一节，每条一段：

- 每条以动词开头，表明变更类别：

  | 开头 | 类别 | 发布说明中的分类 |
  |---|---|---|
  | 新增 | 增加了原先没有的功能 | 新增 |
  | 优化、改进、增强、调整、更新、重新 | 改变了已有功能 | 改进 |
  | 发布 | 仅用于首个版本 | 改进 |
  | 修复 | 纠正了错误 | 修复 |

- 修复类以“修复……的问题”的句式描述问题本身，不描述原因及实现方式；
- 一条中包含多项同类改动时，先写总述，再以冒号引出具体内容；
- 不写技术细节，如代码、协议、库的名称，除非玩家需要据此采取行动。

## 5 文言

文言译文用于“文言”界面语言，应：

- 与中文原文意义一致，不增删内容；
- 沿用既有译名：电脑为“机”，五子棋为“连珠”，落子为“着”，设置为“规制”，更多为“杂录”，匹配为“随缘”，好友为“良友”；
- 标点同第 4.1 条；数字一律以汉字书写。

## 6 英文

英文译文用于“English”界面语言，应：

- 使用英国拼写（Oxford spelling），如 colour、centre、recognise，与 ISO 文件一致；
- 使用正式、完整的句子，不使用缩写形式（don't、can't 等）；
- 不使用长破折号（— 及 –），以逗号、分号或括号代替；
- 界面元素名称首字母大写，不加引号，如 View board、Settings；
- 更新日志以动词过去式开头，如 Added、Improved、Fixed。

## 7 发布说明

GitHub Release 的发布说明由 `node scripts/changelog.mjs notes 版本号` 根据更新日志自动生成，不手工编写。结构固定为：

1. 概要表：版本号、版本类型、发布日期、联机协议、支持平台；
2. 变更内容：按新增、改进、修复分类列出；
3. 兼容性；
4. 获取与安装。

已发布版本的发布说明需要更正时，先修改更新日志，再以生成结果更新该 Release：
`gh release edit v版本号 --notes-file <(node scripts/changelog.mjs notes 版本号)`。

## 8 项目文档

- 文档以编号的章节组织，必要时使用表格；
- 首段说明文档的目的及适用范围；
- 操作步骤使用编号列表，命令放在代码块中；
- 文件、命令、变量名使用代码格式。

## 9 检查

`tests/text.test.ts` 自动检查游戏内说明文字的下列事项，不符合时 CI 不通过：

- 译文齐全；
- 中文不混用半角标点；
- 引号、括号成对；
- 段落以句号结尾；
- 英文不含长破折号；
- 更新日志每一条以表明变更类别的动词开头；
- 更新日志的版本号顺序正确，并且与 `package.json` 一致。
