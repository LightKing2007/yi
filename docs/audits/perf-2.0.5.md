## 3 渲染帧（TST-042）

3.1 方法与 [perf-2.0.4.md](perf-2.0.4.md) 第 3.1 条、第 3.3 条相同：窗口 1320×900，设备像素比 2，显示器 120 Hz；只统计主循环 `frame` 的回调，扣除场景脚本在帧内同步执行的步骤；每个局面从重新载入的开始菜单进入。浏览器中 `performance.now()` 的精度为 0.1 毫秒（页面未启用跨源隔离），主循环耗时的数值均在 1 毫秒以下，相差 0.1 至 0.2 毫秒即为一至两个计时刻度。

3.2 开始菜单（静止，默认“黄昏”光影，正常模式，600 帧，连续测 3 次）：

| 项目 | 第 1 次 | 第 2 次 | 第 3 次 | 2.0.4 |
|---|---|---|---|---|
| 帧率（帧 / 秒） | 120.0 | 120.0 | 120.0 | 114.4 |
| 主循环耗时 p50 / p95 / 最大（毫秒） | 0.2 / 0.5 / 0.6 | 0.3 / 0.5 / 0.6 | 0.3 / 0.5 / 0.7 | 0.1 / 0.2 / 0.6 |
| 帧间隔 p50 / p95 / 最大（毫秒） | 8.3 / 9.0 / 9.4 | 8.3 / 8.8 / 9.4 | 8.3 / 9.1 / 10.6 | 8.3 / 8.5 / 75 |
| 每秒新分配的 JS 内存 | 约 1.2 MB | 约 1.2 MB | 约 1.3 MB | 约 1.0 MB |

3.3 对局中的典型局面（“动画”为场景时间线的全部帧，“停留”为其后的 360 帧）：

| 局面 | 阶段 | 帧数 | 帧率 | 主循环耗时 p50 / p95 / 最大（毫秒） | 帧间隔 p50 / p95 / 最大（毫秒） | 每秒新分配 |
|---|---|---|---|---|---|---|
| 五子棋禁手标记 `renju-marks` | 动画 | 120 | 120.0 | 0.2 / 0.5 / 4.1 | 8.3 / 9.3 / 9.4 | 约 2.1 MB |
| | 停留 | 360 | 120.0 | 0.2 / 0.5 / 0.8 | 8.3 / 8.6 / 9.4 | 约 1.7 MB |
| 五子棋胜利与击散 `gomoku-win` | 动画 | 462 | 120.1 | 0.3 / 0.7 / 4.1 | 8.3 / 8.7 / 9.4 | 约 3.1 至 4.2 MB |
| | 停留 | 360 | 120.4 | 0.2 / 0.5 / 0.6 | 8.3 / 9.3 / 9.4 | 约 2.5 至 2.8 MB |
| 围棋点目 `go-score`（9 路） | 动画 | 330 | 119.3 | 0.2 / 0.6 / 0.7 | 8.3 / 8.5 / 25.1 | 约 5.3 MB |
| | 停留 | 360 | 120.0 | 0.2 / 0.6 / 0.7 | 8.3 / 9.3 / 9.4 | 约 5.9 MB |
| 19 路接近满盘（直接摆 289 子） | 停留 | 360 | 120.0 | 0.3 / 0.5 / 0.6 | 8.3 / 8.5 / 9.3 | 约 7.2 MB |

- `gomoku-win` 测了两次，“每秒新分配”一项两次分别为 4.2、3.1 MB（动画）与 2.8、2.5 MB（停留），以范围列出。该项以每 100 毫秒采样的 JS 堆增量估算，受垃圾回收时机影响，同一局面两次测量相差约 30%。
- `go-score` 动画段帧间隔的最大值 25.1 毫秒出现在第 90 帧，即场景脚本在帧内同步判死的一帧（正式游戏中判死在后台线程），2.0.4 的报告中同样扣除了这一步骤的主循环耗时（最长 15.3 毫秒）。
- 动画段主循环耗时的最大值 4.1 毫秒出现在进入对局的过渡中，为单帧。

3.4 与 2.0.4 报告的差异及对照测量：主循环耗时的 p50、p95 各局面均比 2.0.4 报告高约 0.1 至 0.3 毫秒（开始菜单由 0.1 / 0.2 毫秒变为 0.2 至 0.3 / 0.5 毫秒），按相对值超过 20%。为区分代码与测量环境的影响，在同一浏览器、同一时段中运行 2.0.4 报告所测的提交 `562edde`：

1. 2.0.4 时的依赖（Vite 7.3.6 等）不在本机缓存中，未联网下载；改为以当前的依赖运行 `562edde` 的源码。其间的依赖升级（#36 至 #39）除 `vite.config.ts` 两行外未改动源码，对照时一并套用这两行；
2. 结果：开始菜单（正常模式，600 帧，连续 3 次）主循环耗时 p50 / p95 为 0.2 / 0.5 毫秒，与 2.0.5 相同；`gomoku-win` 的动画段为 0.3 / 0.6 / 4.4 毫秒、每秒新分配约 3.2 MB，停留段为 0.3 / 0.4 / 0.6 毫秒、约 2.6 MB，与 2.0.5 相当，动画段同样在进入对局的过渡中出现约 4 毫秒的单帧峰值；
3. 结论：2.0.4 与 2.0.5 的代码在同一环境中的主循环耗时相同，与 2.0.4 报告数值的差异来自测量环境（浏览器版本、依赖升级后开发模式产出的代码等），不是代码的退步。帧时间（帧间隔）是 TST-042 的度量，各局面 p95 均不超过 9.3 毫秒，与 2.0.4 相当。

3.5 结论：各局面帧间隔的 p95 不超过 9.3 毫秒，满足 TST-042 对参考机 p95 ≤ 16.7 毫秒的要求；逐帧分配仍随盘面上的棋子数增加（19 路接近满盘约 7.2 MB / 秒），整改见 P2-18。
