## 2 确定性与故意破坏验证

| 范围 | 测试及观察 |
|---|---|
| 邮箱保护 | 新增七条测试；十个实现变异均触发预期失败，恢复后通过。涵盖随机 nonce、完整认证、记录与用途及密钥编号绑定、旧密钥读取、独立查找密钥、非法格式和密钥复制 |
| UID | 新增四条测试；四个实现变异均触发预期失败，恢复后通过。独立 Python 答案为 `7KM4P9D2`，全部 248 种单字符替换均拒绝；校验不保证识别所有换位，也不提供身份认证 |
| 账号仓储 | 新增六条测试；账户创建、同意记录、重复邮箱、失败回滚、有限碰撞重试、数据库唯一约束、不可变 UID 及注销后不复用均覆盖 |
| 迁移测试 | 按结构第 2 版调整六条既有测试；与仓储测试合计十四个实现变异均触发预期失败，恢复后通过，包含禁用备份、重复迁移、失败提交及放行高版本数据库 |

2.1 HMAC 独立答案使用已有 Python 标准库计算：32 个字节 `03` 的密钥，对 UTF-8 内容 `["yi:email-lookup",1,"player@example.com"]` 计算 HMAC-SHA-256，结果为 `5fb0191c3bf2928d6655ca0996a3bc66709b3490d35528edf02bb510b45fe430`，与模块结果一致。

2.2 测试不依赖机器执行速度。UID 随机源边界用固定字节核对；密码并发用可控 Promise；账号时间使用固定毫秒值。现有 Python、Node 与项目依赖均未新增全局安装。

## 3 数据库迁移与查询计划

3.1 在项目缓存目录创建结构第 1 版数据库，写入一条虚构游客与其围棋段位，关闭后用默认迁移重新打开。结构升为第 2 版；升级前后用户和段位行的序列化内容一致。自动备份存在，以只支持结构第 1 版的迁移清单打开备份，版本仍为 1。

3.2 以 1,001 个虚构账号捕获仓储实际准备的 SELECT，并运行 `EXPLAIN QUERY PLAN`。查询计划如下：

| 查找条件 | 账号表计划 | 用户表计划 |
|---|---|---|
| `email_lookup = ?` | `SEARCH accounts USING INDEX uq_accounts_email_lookup (email_lookup=?)` | `SEARCH users USING INTEGER PRIMARY KEY (rowid=?)` |
| `public_id = ?` | `SEARCH accounts USING INDEX uq_accounts_public_id (public_id=?)` | `SEARCH users USING INTEGER PRIMARY KEY (rowid=?)` |
| `user_id = ?` | `SEARCH accounts USING INDEX uq_accounts_user_id (user_id=?)` | `SEARCH users USING INTEGER PRIMARY KEY (rowid=?)` |

3.3 三项均无 SCAN。另在临时探针数据库故意移除邮箱索引，查询计划检查确实因全表扫描失败；恢复原探针文本，未修改产品实现。此处验证查询路径，不是容量或吞吐量测试。

3.4 账号默认结构现为第 2 版。现有已发布版本只支持第 1 版，因此本分支构建不能直接用于生产唯一副本；回滚须使用匹配版本的数据库备份。账号与会话等后续迁移必须按配套发布边界安排。
