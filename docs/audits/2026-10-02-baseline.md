## 2 审查发现与整改

每项发现按以下格式列出：问题类型、所属对象（S1 至 S16）、问题描述、整改后的规定、改进理由。“整改后的规定”列出的规则编号即为工程规范（YI-STD-001）中替代原规定的条款。

### 2.1 严重

**F-01 数据丢失：存档损坏时被静默覆盖**（S9，逻辑漏洞）

- 问题：`server/store.ts` 读取 `yi-ratings.json` 失败时，以空数据启动，异常仅以注释“第一次运行”吞掉。只要文件存在但损坏（截断、磁盘错误、手工误编辑），2 秒后的首次写盘就会以空数据覆盖原文件，全部段位永久丢失。
- 整改：DAT-050 至 DAT-053。文件不存在才视为首次运行；文件存在但解析失败时，严禁启动，必须保留原文件并以退出码 65 退出。
- 理由：遵循故障安全（fail-closed）原则。数据层的未知状态必须中止服务，而不是带着错误继续运行，参见 ISO 22301:2019 第 8.4 节。

**F-02 数据无备份**（S8，缺失）

- 问题：段位数据只有一份，存于单台服务器的单个文件。
- 整改：DAT-060 至 DAT-066。设定 RPO ≤ 24 小时、RTO ≤ 1 小时，按 3-2-1 原则保存，并定期演练恢复。
- 理由：没有备份时，任何一次 F-01 类故障、误操作或磁盘故障都会导致永久丢失，不满足 GB/T 22239—2019 第二级“数据备份恢复”的要求。

### 2.2 高

**F-03 运行时组件超出支持期**（S14，过时）

- 问题：游戏随安装程序分发 Electron 38.8.6。Electron 官方只维护最新的三个主版本，当前为 42、43、44，因此 38 已不再获得安全修复。`npm audit` 报告 2 项高危漏洞，均为释放后重用。
- 整改：VER-030、SEC-060。分发的 Electron 必须处于官方支持期内，高危漏洞 30 日内修复。
- 理由：桌面端直接运行在玩家计算机上，渲染进程漏洞会危及玩家主机安全。

**F-04 服务器登录面暴露**（S8，安全缺陷）

- 问题：`sshd_config` 中为 `PermitRootLogin yes`、`PasswordAuthentication yes`，主机防火墙 UFW 未启用，仅依赖云安全组。
- 整改：SEC-040 至 SEC-044。SSH 仅允许密钥登录，主机防火墙必须启用并默认拒绝，安全组与主机防火墙双层放行同一端口清单。
- 理由：口令登录 root 是公网主机最常见的入侵途径，见 CIS Ubuntu 24.04 Benchmark 第 5.1 节；纵深防御要求两层访问控制，见 GB/T 22239—2019。

**F-05 主分支保护可被绕过**（S1，规范漏洞）

- 问题：禁止直接推送 `main` 只依靠本地 `pre-push` 钩子。`git push --no-verify` 可以绕过它，未执行 `npm install` 的克隆中钩子也不生效。免费私有仓库无法开启 GitHub 分支保护。
- 整改：OPS-005、OPS-006。CI 在每次推送 `main` 后校验提交来源：提交说明必须以 `(#PR 编号)` 结尾，或为发版脚本生成的 `release: v版本号`，否则 CI 失败并告警。同时登记决策项 D-2：升级 GitHub Pro 或公开仓库，以启用服务端分支保护。
- 理由：只在客户端执行的控制不构成有效控制，必须在服务端有对应的检测手段。

**F-06 服务进程隔离不足**（S8，安全缺陷）

- 问题：`systemd-analyze security yi` 的暴露评分为 8.3（满分 10，越低越安全）。
- 整改：SEC-045，评分必须 ≤ 4.0，并列出必须增加的 systemd 选项。
- 理由：游戏服务端直接面向公网，进程被攻破时，沙箱是阻止横向移动的最后一道防线。

**F-07 入站消息无速率限制**（S11，缺失）

- 问题：服务端只限制单条消息大小（4096 字节）和单 IP 连接数（8）。不限制单连接的消息频率，也不限制握手前的空闲时间。单个恶意客户端可以无限发送 `queue`/`unqueue`、`name` 等消息，占满事件循环。
- 整改：API-040 至 API-046，采用令牌桶限速、握手超时和违规累计断开。
- 理由：见 OWASP API Security Top 10:2023 的 API4（资源消耗不受限制）。

**F-08 明文传输身份凭据**（S11，安全缺陷）

- 问题：联机使用 `ws://`，匿名身份 `uid` 和重连令牌以明文传输，可被链路上的第三方窃取并冒用，冒用者将继承对方的段位。
- 整改：SEC-010 至 SEC-013。3.0 版本前必须切换到 `wss://`；在此之前登记为已接受风险，并且严禁在明文通道上引入账号口令。
- 理由：见 GB/T 22239—2019 关于通信传输保密性的要求，以及 OWASP ASVS 5.0 第 12 章。

**F-09 安装程序无完整性校验**（S16，供应链缺陷）

- 问题：下载页面以 `http://` 分发安装程序，未公布校验和；`deploy.sh` 从 GitHub 下载后直接上传，也不校验。
- 整改：OPS-030、OPS-031、SEC-070。发布必须生成 `SHA256SUMS`，下载页面必须展示校验和，上线脚本必须核对校验和。
- 理由：见 SLSA v1.0 关于构建产物完整性的要求。未签名且无校验和的安装程序可能被中间人替换。
