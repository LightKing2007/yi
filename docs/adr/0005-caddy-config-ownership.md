# 0005 Caddy 配置在仓库之间的分工

| 项目 | 内容 |
|---|---|
| 状态 | 接受 |
| 日期 | 2026-10-13；补录于 2026-10-14 |
| 决定者 | 项目所有者 |
| 相关 | #116；LightKing2007/LightsWeb#1；路线图第 6 章；[0004](0004-domain-and-tls-early.md) |

## 1 背景

1.1 按 [0004](0004-domain-and-tls-early.md)，服务器 47.108.181.240 以 Caddy 作为对外的入口。项目所有者计划这台服务器以后承载多个网站，弈只是其中之一。

1.2 Caddy 只能有一个主配置 `/etc/caddy/Caddyfile`，但各网站的配置分属不同的仓库、由不同的人维护。

## 2 决策

2.1 Caddy 本身的安装与主配置由 LightsWeb 仓库管理（`config/caddy/`）。主配置只有一行 `import /etc/caddy/sites/*.caddy`。

2.2 每个网站的站点配置由该网站的仓库维护，安装为 `/etc/caddy/sites/<站点>.caddy`。弈的站点配置为本仓库的 `scripts/server/yi.caddy`，以 `npm run deploy -- install-caddy` 安装：先以整套配置校验，再平滑重载，经 HTTPS 检查通过才算完成，不通过即恢复原文件。

2.3 新增网站时只在该网站的仓库中添加站点配置，主配置不须修改。

## 3 备选方案

| 方案 | 不采用的原因 |
|---|---|
| 全部配置放在弈的仓库 | 补录时整理，当时未讨论：其他网站的配置与弈无关，改动它们须经弈的 PR 与 CI |
| 全部配置放在 LightsWeb 仓库 | 补录时整理，当时未讨论：弈的站点配置与服务端紧密相关（屏蔽 `/healthz`、`/metrics`，转发到 8443），应与服务端一同评审、测试与上线 |
| 在服务器上直接编辑 | 补录时整理，当时未讨论：无法评审与回溯，违反 `yi.caddy` 文件头“严禁在服务器上直接改动”的约定 |

## 4 后果

4.1 两个仓库各管一层：弈改动站点配置不影响其他网站，Caddy 的平滑重载也不断开已建立的联机。

4.2 主配置须先于站点配置安装；`install-caddy` 在主配置没有引入站点目录时拒绝安装。

4.3 #116 的计划中，“以 IP 或未登记的域名访问时默认拒绝”与公共响应头也由 LightsWeb 的主配置负责；但 2026-10-13 安装的主配置只有 `import` 一行，这两项尚未实施。现状下以 IP 或未登记的域名经 HTTPS 访问时 TLS 握手失败，不会返回任何站点；`yi.caddy` 文件头的相应说明与现状不符，待 LightsWeb 补上这两项或更正说明。
