# 0004 域名与 TLS 提前于 3.0 启用

| 项目 | 内容 |
|---|---|
| 状态 | 接受 |
| 日期 | 2026-10-12（决定）；2026-10-13 服务器启用 HTTPS；补录于 2026-10-14 |
| 决定者 | 项目所有者 |
| 相关 | 路线图第 6 章（阶段 4）、决策 D1、D6；整改项 P2-05；#115、#116、#117、#118、#125；SEC-010 至 SEC-013、API-040、API-061；[0005](0005-caddy-config-ownership.md) |

## 1 背景

1.1 路线图原定：ICP 备案期间游戏直连 `ws://IP:8443`，域名不对外提供服务；备案通过后，域名、TLS 与客户端地址的切换随 3.0（账号系统、协议 v4）一并发布，只强制更新一次。

1.2 2026-10-12 域名 `lightking.com.cn` 的 ICP 备案通过（渝ICP备2025066996号-2）。此时 3.0 依赖的数据库（阶段 5）与账号系统（阶段 6）都还没有开始。

## 2 决策

2.1 服务器侧的域名与 TLS 提前启用，不等 3.0：

- `yi.lightking.com.cn` 由服务器上的 Caddy 以 HTTPS 提供，证书由 Let's Encrypt 签发并自动续期，经 80 端口的 HTTP 验证；Caddy 反向代理到本机的游戏服务端 `127.0.0.1:8443`；
- 安全组与 UFW 放行 80、443；8443 在过渡期内保留，供 2.x 客户端直连，3.0 起关闭；
- 下载页面与面向玩家的地址改为域名（#117），下载页面地址为 `https://yi.lightking.com.cn/`（#125），页脚展示 ICP 备案号（#118）。

2.2 经代理转来的连接在服务端看来都来自本机，服务端按 `X-Forwarded-For` 的最后一项（Caddy 所见的对端地址）取客户端的真实地址，按 IP 的限制都按真实地址计数；只信任来自本机的这个头（#115，`server/clientIp.ts`）。`/healthz`、`/metrics` 在 Caddy 一侧屏蔽，服务端也不回应经代理转来的请求，两处互为备份。

2.3 游戏客户端改用 `wss://` 与收紧 CSP（P2-05）仍未实施，何时发布另行决定。

## 3 备选方案

| 方案 | 不采用的原因 |
|---|---|
| 按路线图原定，随 3.0 一并启用 | 3.0 尚远；提前启用可让下载页面先走 HTTPS，并在 3.0 之前把代理、证书与真实地址的取法跑稳，3.0 时只需切换客户端 |
| 由游戏服务端自己提供 TLS | 补录时整理，当时未讨论：服务端以无特权的用户运行，不能监听 443；证书的申请与续期要自己实现；同一台服务器以后要承载多个网站，443 只能由一个程序监听 |
| 服务端信任 `X-Forwarded-For` 的第一项 | 第一项由客户端自己填写，可以伪造，会使按 IP 的限流失效 |

## 4 后果

4.1 2026-10-13 起 `https://yi.lightking.com.cn/` 可以访问，HTTP 以 308 跳转到 HTTPS，WebSocket 经代理升级正常。

4.2 服务器多了一个对外的程序（Caddy）和两个端口（80、443）。

4.3 过渡期内 8443 仍对外开放，客户端的联机流量仍为明文；3.0 起服务端设 `HOST=127.0.0.1`，关闭 8443（SEC-011）。

4.4 Caddy 的配置如何在仓库之间分工，见 [0005](0005-caddy-config-ownership.md)。
