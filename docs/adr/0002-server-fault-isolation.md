# 0002 服务端异常隔离与错误编号

| 项目 | 内容 |
|---|---|
| 状态 | 接受 |
| 日期 | 2026-10-10（#109 合并）；补录于 2026-10-14 |
| 决定者 | 按规范 API-023 实施，项目所有者指定实施顺序 |
| 相关 | 整改项 P2-15（审计发现 A-02）；#109；API-023、EDGE-002；路线图第 8.1 节 |

## 1 背景

1.1 联机服务端是单个 Node.js 进程，全部对局都在内存中。此前处理消息、断线或定时检查时，任何一个未预期的异常都会使整个进程退出：全部对局中断，最多 2 秒内尚未写盘的段位变化丢失，systemd 在 3 秒后重启。

1.2 API-023 要求未预期的异常记录完整调用栈与错误编号，只向客户端下发错误编号，不下发异常内容。

## 2 决策

2.1 `RoomServer` 在处理消息、断线与每 0.25 秒的定时检查时捕获未预期的异常，只处理出错的那一项：

| 入口 | 出错时的处理 |
|---|---|
| 处理消息 | 只以 1011 断开发消息的连接，对局保留席位，可在 60 秒内重连 |
| 断线 | 移除断线的玩家，放弃其房间，对手以 1011 断开 |
| 定时检查 | 放弃出错的配对、房间或玩家，其余照常检查；出错的一项必须移除，否则每次检查都会再出错 |

2.2 每次出错写一行 `internal.error`（error 级别），附 `errorId`（UUID v4）、调用栈，以及所处理的玩家、房间或配对的编号。

2.3 **协议**：`error` 消息增加可选字段 `errorId`，被断开的玩家看到“服务器出现问题，请稍后再试”，客户端把错误编号写入本机日志，玩家反馈问题时可与服务端日志对照。协议版本号不变；路线图第 8.1 节写明协议 v4 保留这个字段。

## 3 备选方案

| 方案 | 不采用的原因 |
|---|---|
| 维持进程退出、由 systemd 重启 | 一个缺陷即中断全服对局，违反 API-023、EDGE-002 |
| 捕获后继续处理出错的那一项 | 补录时整理，当时未讨论：出错的状态可能已不一致，继续处理可能写坏段位或使定时检查反复出错 |
| 只在服务端日志记录，不下发错误编号 | 玩家反馈问题时无法与服务端日志对应 |

## 4 后果

4.1 单个缺陷只影响相关的一两名玩家，其余对局照常进行。

4.2 上线后 60 分钟内的自动回滚（OPS-047）以 `internal.error` 计数服务端内部错误，不须另外改动。

4.3 只增加可选字段，新旧客户端与服务端互相兼容（VER-002）。
