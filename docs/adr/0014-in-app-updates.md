# 0014 启动检查版本与游戏内更新

| 项目 | 内容 |
|---|---|
| 状态 | 接受 |
| 日期 | 2026-11-02 |
| 决定者 | 项目所有者 |
| 相关 | ARC-060、SEC-032、SEC-070、决策 0007 |

## 1 背景

1.1 原有更新提示在联机握手后才出现，点击后须进入官网下载并手动安装。协议第 4 版的联机握手须登录，不能借启动检查接管账号在其他设备上的连接。

1.2 项目所有者要求启动时检查版本，并通过原有提示提供游戏内下载和安装；确认先完成 Windows、Linux，macOS 暂保留官网下载，并同意项目内安装 electron-updater。

## 2 决策

2.1 桌面端启动时独立检查官网，不建立对战 WebSocket，不依赖登录。检查失败不阻断单机；主进程限制更新源为既有 HTTPS 官网。macOS 使用官网既有 SHA256SUMS 发现对应架构的新版本。

2.2 Windows 的 NSIS 与 Linux 的 AppImage 使用 electron-updater，禁止自动下载、退出时自动安装和降级。玩家点击下载，按发布清单校验 SHA-512 后才提供重启安装；对局、匹配或等待好友期间不允许重启安装。macOS 沿用决策 0007，不绕过签名验证。

2.3 官网同步发布 latest.yml、latest-linux.yml 与四个安装程序，全部先按 Release 的 SHA256SUMS 校验，再原子切换。旧 Release 没有更新清单时仍可同步其安装程序；只出现一份清单时拒绝同步。

2.4 先使用完整文件下载，关闭差分下载，不新增 blockmap 分发路径。更新功能仍须按三平台发布验证；Windows 权限提示与 Linux AppImage 目录写权限须实机确认。

## 3 备选方案

| 方案 | 不采用的原因 |
|---|---|
| 启动时登录联机服务器 | 会接管同一账号在其他设备的对战连接，且未登录玩家仍收不到更新 |
| 自行编写替换程序和安装脚本 | 需自行处理平台权限、退出与文件替换恢复；采用现有安装程序及配套更新器 |
| 全平台使用 Electron 内置 autoUpdater | 不匹配现有 Windows NSIS 与 Linux AppImage；macOS 仍受签名条件限制 |

## 4 后果

4.1 增加 MIT 许可的运行时依赖 electron-updater，纳入分发漏洞检查；Electron 层的允许包表与分层测试同步更新。

4.2 已安装的 4.0.0 不会自行获得新能力。玩家须按原方式安装首个带更新器的版本，之后的新版本才可通过游戏内更新安装。

4.3 新游戏发布前须先上线提供清单的官网版本，并同步游戏安装程序与清单。本决策不授权生产部署或发布游戏版本。
