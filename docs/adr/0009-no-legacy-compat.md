# 0009 按尚无玩家的前提，不保留旧数据与旧客户端的兼容

## 1 背景

1.1 游戏目前只在项目所有者与朋友圈中小范围使用（决策 D7）。阶段 5 为保住已有玩家的段位，做了导入 `yi-ratings.json`、按文件修改时间同步、数据库与 JSON 双写一个版本周期（决定 D5-1）等工作；服务端与上线脚本中还有为旧版本客户端、旧版本服务端保留的过渡代码：`EXTRA_PORTS` 端口过渡、对外开放的 8443 直连与 http 下载地址、上线脚本中为 2.0.6 及以前的服务端写的分支与一次性的 `migrate-layout`。

1.2 这些兼容工作使代码与运维多了两套存储格式、两种连接方式，以及只在过渡期才用得到的分支，测试与文档都要随之维护。

## 2 决策

2.1 按游戏尚无玩家看待：不保留此前的任何玩家数据，也不再兼容旧版本客户端。

2.2 删除旧数据的兼容：服务端只用数据库一种存储，删除旧段位存档 `yi-ratings.json` 的读写、导入、同步与双写（`server/store.ts`、`server/db/legacy.ts`、环境变量 `YI_DATA`）；表结构中段位变化的原因不再有 `import`。决定 D5-1 作废。

2.3 删除旧客户端的兼容：客户端改连 `wss://yi.lightking.com.cn/ws`，CSP 的 `connect-src` 只放行该地址（整改项 P2-05）；服务端只监听本机（`HOST=127.0.0.1`），8443 不再对外开放；下载页面只经 `https://yi.lightking.com.cn/` 访问；删除 `EXTRA_PORTS` 与上线脚本中为旧服务端保留的分支。

2.4 下一版要求所有玩家安装新版客户端，按 VER-002 递增主版本，为 3.0.0。路线图原定的“3.0（账号系统与协议第 4 版）”顺延为 4.0。决定 D5-2（2.0.8）作废。

2.5 上线 3.0.0 时删除服务器上的旧段位存档及其本地备份；删除前由项目所有者把一份副本下载到本机（DAT-066）。

2.6 保留：数据库的迁移框架与迁移前备份（以后的版本加表要用）；新版本提示（`YI_LATEST`，以后每次发版都靠它提醒玩家更新）。

## 3 备选方案

| 方案 | 不采用的原因 |
|---|---|
| 按决定 D5-1 双写一个版本周期，导入旧段位 | 为极少数测试数据维护两套存储与同步逻辑，不值得 |
| 只删旧数据兼容，客户端的切换仍随账号那一版发布 | 项目所有者决定一并删除；尚无玩家时强制更新没有实际代价 |
| 版本号仍为 2.0.8，记为 VER-002 的例外 | 强制更新递增主版本是规范的明文规定，没有理由破例 |

## 4 后果

4.1 3.0.0 起，2.0.x 客户端连不上服务器，必须安装新版。3.0.0 上线失败时仍可回滚到 2.0.7 的服务端：协议相同，新客户端经 Caddy 照常连接；但 2.0.7 读写的是旧存档，而旧存档已在上线时删除，回滚期间的段位从零开始，再次上线 3.0.0 时不导入。

4.2 3.0.0 上线需要以 root 执行的配置修改：`yi.service`（`HOST=127.0.0.1`、去掉 `YI_DATA`）、备份定时器；安全组与 UFW 关闭 8443 由项目所有者操作。

4.3 服务端存储、上线脚本与测试随之简化：删除 `server/store.ts`、`server/db/legacy.ts` 及其测试，存储只有数据库一种。
