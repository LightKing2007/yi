## 1 范围

1.1 影响两个及以上层、引入运行时依赖、改变协议或数据格式的决策，必须在本目录记录（ARC-060）；新增层或调整依赖方向，必须先提交记录（ARC-014）。服务器结构、运维方式、发行方式上需要项目所有者拍板、日后可能被追问“为什么这样做”的决策，同样在本目录记录。

1.2 路线图第 3 章的 D1 至 D12、整改路线图第 7 章的 D-1 至 D-4 视为已接受的记录，不在本目录重复。

## 2 写法

2.1 文件名为 `NNNN-英文短标题.md`，编号四位、依次递增、不复用。

2.2 每条记录以信息表开头，写明状态、决定日期、决定者、相关 PR；正文统一分为以下 4 节：

1. 背景：要解决什么问题，当时的约束与实测数据；
2. 决策：决定了什么，数值与范围写清楚；
3. 备选方案：考虑过的其他做法，以及不采用的原因；
4. 后果：带来的好处、代价、遗留事项。

2.3 状态为提议、接受、废弃、取代之一。记录接受后不改写正文；决策改变时新写一条记录，把旧记录的状态改为“取代（见 NNNN）”或“废弃”。

2.4 事后补录的记录在信息表中注明“补录”，依据当时的 PR 说明与会话交接记录整理；当时没有讨论过、补录时才整理的备选方案，须在该项中注明。
