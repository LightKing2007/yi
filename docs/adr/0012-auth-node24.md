# 0012 账号会话事务的最低 Node.js 版本调整为 24

| 项目 | 内容 |
|---|---|
| 状态 | 提议（本批实现采用，随 PR 审查） |
| 日期 | 2026-10-31（Asia/Shanghai） |

| 相关 | [0008](0008-node-sqlite.md) 第 2.3 条；[阶段 6、7](../plan/phase6-7.md)；SEC-021、DAT-040、VER-031 |

## 1 背景

1.1 现有包声明支持 Node.js 22.13，但 CI、服务器与 `.nvmrc` 已使用 24。登录会话需要原子更新口令、认证世代及会话，注册与验证码还需共享外层事务；嵌套操作不能提前提交，撤销通知也不能在事务提交前发出。

1.2 Node.js 官方 [v24.22.2 SQLite 文档](https://github.com/nodejs/node/blob/v24.22.2/doc/api/sqlite.md#databaseistransaction) 明确 `database.isTransaction` 自 v24.0.0 提供。继续声明 22.13 会让不支持该属性的运行时错误判断事务状态。已在项目内已有的 Node.js 24.22.2 上通过真实 SQLite 测试验证事务和嵌套保存点。

## 2 决策

2.1 本批将 `package.json` 及锁文件根包的最低 Node.js 声明统一为 `>=24`，README 同步说明；`.nvmrc` 继续为 24，不安装或修改系统运行时。本提议接受后取代 0008 第 2.3 条中最低 22.13 的部分。

2.2 仓储事务通过 `isTransaction` 读取实际 SQLite 状态：外层使用 `BEGIN IMMEDIATE`，嵌套使用保存点。登录会话的独立撤销入口拒绝在外层未提交事务中执行，跨仓储认证流程在最外层提交成功后再通知连接层。

## 3 备选方案

| 方案 | 处理 |
|---|---|
| 只在内存追踪自有事务深度 | 无法识别同一连接上其他仓储已开始的事务，不能可靠阻止提前通知 |
| 所有写入统一使用外层保存点 | 无法保持当前外层 IMMEDIATE 的锁定语义，且仍需识别通知发生时的实际提交状态 |
| 假定事务状态不存在时为 false | 会在嵌套事务中重复 BEGIN 或提前通知，不采用 |

## 4 后果

4.1 未部署账号功能；服务器当前已使用 Node.js 24，无须本批执行远程安装。外部仍使用 Node.js 22 的开发或服务端环境在使用新代码前必须升级。

4.2 这只是最低运行时和事务边界的选择，不替代数据库结构第 3 版迁移、认证压力测试或真实 HTTP/WebSocket 接入验收。
