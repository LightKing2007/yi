# 0013 · 官网独立运行与发布

| 项目 | 内容 |
|---|---|
| 状态 | 接受 |
| 日期 | 2026-10-31 |
| 决定者 | 项目所有者 LightKing |
| 依据 | 项目所有者要求官网与联机程序、账号数据库升级分开；官网统一放在 `/opt/www/yi.lightking.com.cn` |

## 1 背景

官网此前嵌入联机服务端，更新文书必须更换游戏服务端。当前主分支包含结构第 2 至 5 版的账号迁移，而已发布 3.1.0 只支持结构第 1 版；不能为更新文书而连带升级游戏数据库。

## 2 决策

官网使用独立的 `web.cjs`、`yi-web.service` 和发布记录，目录为 `/opt/www/yi.lightking.com.cn`。主页、下载页、资源和文书沿用现有渲染器与无脚本交互；独立进程只监听本机 8444。联机继续由现有服务处理，网站发布不调用联机启动、迁移、维护或重启命令。

官网安装包目录独立维护，来源须为已发布的游戏 Release；网站代码更新不更改对玩家提供的游戏版本。安装包只保存在 `/opt/www/yi.lightking.com.cn/downloads/`，服务器仅保留当前版本；历史版本由 GitHub Release 保存，不在 `/opt/yi` 留存。网站构建使用提交号标识版本，不更改 `package.json` 的游戏版本，也不把草案文书版本当作认证同意版本。

网站构建检查实际解析的依赖清单，禁止引入数据库、账号和联机模块。生产服务无数据库与密钥访问权限。网站健康检查只供本机直连，不能经公网或代理读取。

独立部署须校验产物、校验下载包、保留上一版、原子切换、检查健康和公网路由，失败恢复。Caddy 仅把 WebSocket 交给联机服务，其余公开页面交给官网；已有 `/ws` 地址继续可用。

## 3 备选方案

继续整体发布会扩大文书更新的影响范围。完全静态导出需要另行改写当前按请求头推荐安装程序的行为。采用独立 Node HTTP 进程可复用已验证页面与下载限制，不增加第三方依赖。

## 4 后果

网站与游戏各有运行和回滚记录，网站故障不应重启游戏，游戏数据库升级也不再是网站更新的前提。初期保留旧传输测试使用的页面适配能力；生产联机入口随拆分停止装配官网。发布、部署、监控和安装包更新须按独立官网流程维护。
