| 项目 | 内容 |
|---|---|

参考：ISO/IEC/IEEE 29119-1:2022、-3:2021、-4:2021；GB/T 15532—2008；GB/T 25000.51—2016；ISO/IEC 25010:2023。

## 1 测试层级

1.1 本项目的测试统一分为五级。每一级的对象、工具、执行时机如下：

| 级别 | 对象 | 工具 | 执行时机 |
|---|---|---|---|
| 单元测试 | `core`、`shared`、`session`、`server` 业务逻辑、`i18n`、`scripts` | Vitest | 每次提交（CI） |
| 集成测试 | 真实 WebSocket 上的客户端与服务端、HTTP 下载接口 | Vitest + 本地端口 | 每次提交（CI） |
| 画面回归 | 特效与界面的关键帧 | `npm run shots` + `compare-shots.mjs` | 修改 `render`、`fx`、`scene`、`ui` 的 PR |
| 平台验证 | 三个平台的安装、首次运行、字体、WebGL、音频、联机 | [checklists.md](checklists.md) 第 3 节 | 每次发布前 |
| 性能基准 | 电脑思考耗时、帧时间、服务端消息处理耗时 | 基准脚本（P2-07 建立） | 每次发布前 |

## 2 覆盖率

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| TST-010 | A | 行覆盖率与分支覆盖率底线统一如下，低于底线时 CI 阻断：`src/core` 行 ≥ 90%、分支 ≥ 85%；`src/shared` 行 ≥ 90%、分支 ≥ 85%；`server` 行 ≥ 85%、分支 ≥ 75%；`src/session` 行 ≥ 85%、分支 ≥ 75%；`src/online` 行 ≥ 75%、分支 ≥ 65%；全项目（不含 `render`、`fx`、`scene`、`ui`、`audio`）行 ≥ 75%。统计范围为 `src` 与 `server`；`electron` 不在单元测试范围内（本文件第 1.1 条），由平台验证覆盖。门槛定义在 `vite.config.ts` 的 `test.coverage.thresholds` | 未知（无覆盖率工具，P1-02 建立） |
| TST-011 | A | PR 中新增与修改的可执行行的覆盖率 ≥ 80% | 未知 |
| TST-012 | B | `render`、`fx`、`scene`、`ui`、`audio` 不计入行覆盖率，以画面回归场景覆盖：每个特效至少 1 个场景，每个界面面板至少 1 张截图。开发用的场景脚本 `src/app/scenarios.ts` 同样不计入：它是画面回归的驱动，以画面回归完整运行验证 | 部分满足 |
| TST-013 | A | 每个已修复的缺陷必须附带一个在修复前失败、修复后通过的回归测试，测试名称必须写明缺陷现象 | 满足 |

## 3 确定性与偶发失败

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| TST-020 | A | 测试严禁依赖真实时钟、真实随机数、执行速度。时间统一经 `setClock` 或 Vitest 假定时器注入；随机数统一传入固定种子；电脑算法统一按固定模拟次数运行 | 部分满足（已修复 1 例；`困难` 五子棋性能断言仍依赖速度） |
| TST-021 | A | 测试之间严禁共享可变状态；每个测试必须在 `beforeEach` 中重建依赖 | 满足 |
| TST-022 | A | CI 严禁对失败的测试自动重试 | 满足 |
| TST-023 | A | 发现偶发失败的测试时，必须在 24 小时内建 Issue 并以 `it.skip` 加 Issue 编号隔离，在 7 日内修复并恢复；隔离中的测试数 ≤ 3 | 满足 |
| TST-024 | A | 单个测试的超时上限统一为 5 秒；电脑自我对弈等长测试必须显式声明超时，且 ≤ 60 秒；全部测试在 CI 上的总时长 ≤ 120 秒 | 部分满足 |

## 4 Mock 规范

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| TST-030 | C | 只允许替换系统边界：时钟、随机数、WebSocket 传输、Worker、`localStorage`、文件系统、网络；严禁替换被测模块自身的内部函数，严禁替换 `core` 规则层 | 满足 |
| TST-031 | C | 统一优先使用手写的假实现（如 `FakeWorker`、`MemoryStore`），其次才使用 `vi.fn()`；假实现必须与真实实现实现同一接口，由类型检查保证一致 | 满足 |
| TST-032 | A | 严禁在测试中访问外网；集成测试统一监听 127.0.0.1 的随机端口（端口 0） | 满足 |
| TST-033 | A | 每个测试结束时必须释放全部资源（端口、定时器、临时目录）；临时目录统一创建在 `os.tmpdir()` 下，并在 `finally` 中删除 | 满足 |

## 6 性能基线

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| TST-040 | C | 参考机型统一为：本地 Apple M4 / 32 GB（以下称“参考机”）；CI 为 GitHub `ubuntu-latest`（以下称“CI 机”） | 满足 |
| TST-041 | A | 电脑单步思考耗时上限：五子棋困难，参考机 p95 ≤ 1.5 秒，CI 机 ≤ 4.0 秒；围棋困难，参考机 ≤ 3.2 秒（预算 3.0 秒加 0.2 秒容差）；围棋普通 ≤ 1.4 秒 | 部分满足（仅五子棋有断言） |
| TST-042 | C | 渲染帧时间：参考机 1320×900 窗口下 p95 ≤ 16.7 毫秒；无独立显卡的 Windows 计算机 p95 ≤ 33 毫秒 | 未知（P2-07 测量） |
| TST-043 | C | 桌面版冷启动到开始菜单可交互 ≤ 3 秒（参考机）；渲染进程内存 ≤ 400 MB | 未知 |
| TST-044 | A | 前端主包 gzip 后 ≤ 150 KB（现为 75 KB）；单个 Worker 包 gzip 后 ≤ 30 KB；安装程序 ≤ 130 MB | 满足 |
| TST-045 | C | 服务端：在 2 vCPU 服务器上，500 条并发连接、每条每秒 2 条消息时，消息处理耗时 p99 ≤ 5 毫秒，CPU ≤ 50%，常驻内存 ≤ 256 MB；事件循环延迟 p99 ≤ 50 毫秒 | 满足（P2-07，#95：`npm run loadtest` 与“服务端压测”工作流；2026-10-06 在 CI 上以 500 条连接、每条每秒 2 条消息、服务端限定 2 核实测：处理耗时 p99 ≤ 1 毫秒，CPU 9.3%，常驻内存 161 MB，事件循环延迟 p99 1.7 毫秒） |
| TST-046 | A | 性能基线的测量结果必须记入 `docs/audits/perf-版本号.md`；任一指标较上一版本劣化 > 20% 时，严禁发布 | 满足（2.0.4 起每版发布前记入 `docs/audits/perf-版本号.md`） |
