## 1 PR 检查清单

在 PR 模板中逐项勾选，未勾选的项必须写明“不适用”及原因：

1. 标题符合 OPS-001、OPS-002；只含一个主题（OPS-004）。
2. 本地 `npm run format:check`、`npm run ratchet`、`npm run typecheck`、`npm run test:coverage` 通过（与 CI 的检查一致，OPS-012）。
3. 新增代码满足 [01-coding.md](01-coding.md)；修改的函数已一并整改（[00-general.md](00-general.md) 第 4.3.3 条）。
4. 新增依赖已按 COD-070 说明。
5. 外部输入均经过校验（COD-053、API-010）。
6. 新增错误码已加入错误码表与测试（API-021、API-022）。
7. 改动协议的，已评估兼容性并按 VER-002、VER-003 确定版本号。
8. 改动数据格式的，已提供迁移与版本号（DAT-041、VER-012）。
9. 玩家可见的改动，已写更新日志与译文，并已在三种语言下查看界面（I18N-021）。
10. 改动界面文字的，已重新生成字体子集（I18N-023）。
11. 改动画面的，已运行画面回归（TST-012）。
12. 已回答 [10-edge-cases.md](10-edge-cases.md) 中适用的极端情况（EDGE-001）。
13. 已同步更新受影响的文档（DOC-003）。

## 2 发布前检查清单

1. [整改路线图](../plan/remediation.md) 中期限已到的 P0 项全部完成。
2. `main` 的 CI 成功（OPS-025）。
3. 性能基线已测量且未劣化 20% 以上（TST-046）。
4. 草稿 Release 的附件齐全：四个安装程序、服务端、`SHA256SUMS`、SBOM。
5. 发布说明与更新日志一致。

## 3 平台验证清单

每个平台逐项验证：安装、首次打开（macOS 公证提示、Windows SmartScreen）、开始菜单字体、对局渲染、音频、联机匹配一局、窗口最小尺寸布局、退出后再次打开设置保留、卸载。

## 4 上线后检查清单

1. `/healthz` 的版本号与提交号正确（OPS-046）。
2. 日志首行版本正确，30 分钟内无 `error` 级日志。
3. 下载页面四个安装程序的 SHA-256 与 `SHA256SUMS` 一致。
4. 用旧版本客户端连接，能看到新版本提示。
