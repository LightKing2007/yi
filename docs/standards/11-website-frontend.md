# 网页端前端规范（官网）

适用范围：官方网站全部页面（主页、下载、帮助与支持、法务文书、404 及后续新增页面）。
客户端（游戏）前端不在本规范范围内。
目标：**让后面的页面都长在同一套规则上**——新页面只做内容与组装，不发明新样式、新组件、新依赖。

现状盘点（2026-11-01）：41 个常规页面及 404 回退全部可达（主页、下载、支持目录、34 篇帮助、文书目录、3 份文书）。
核心内容保持无脚本可用；全站有一个可选增强包，帮助目录另有渐进增强检索脚本。统一外壳 `server/page.ts`，共享样式 `server/pageStyle.ts`，全部页面已迁入共享组件与设计变量。

---

## 1 设计风格与理念

### 1.1 理念：以木为枰，以石为子

官网是棋室的延伸，不是营销页。三条不可动摇的原则：

1. **黑白交替**：页面以墨色（.ink）与贝色（.shell）区块交替推进，如同对局黑白交替落子。新增页面沿用同一节奏，不做第三种底色。
2. **内容即装饰**：装饰元素只能是棋类语言——棋盘、棋子、落子、提子、棋钟、段位。不引入与棋无关的插画、图标风格或 3D 炫技。
3. **可达性优先**：所有内容无脚本可读、可下载、可检索；动画只是修饰，`prefers-reduced-motion` 时全部关闭。

### 1.2 视觉语言

| 项 | 规定 |
|---|---|
| 色彩 | 墨色 `#0b0a09` / 贝色 `#f3efe7` 为底；榧木金 `#d6a964` 只用于棋盘与少量强调；印章红 `#b23a2c` 只用于印章、选区、禁手标记 |
| 字体 | 标题宋体（Yi Serif = 思源宋体子集，900/400 两档）；正文系统黑体；数字、版本号、命令用等宽 |
| 字重 | 只有 900（标题）与 400/500（正文、按钮），禁止第三档 |
| 字号 | 全阶梯流式 `clamp()`：hero 48–112、h2 36–80、h3 22–28、导语 16–18、正文 16、辅助 14、注脚 13；禁止断点突变 |
| 行高 | 标题 1.12–1.3，正文 1.75，标签 1.4 |
| 字距 | 栏目标签 0.42em、导航 0.24em、按钮 0.08em、标语 0.3em；标题不额外加字距 |
| 间距 | 页面边距 `--gut: clamp(20px, 5vw, 72px)`；内容最大宽 `--max: 1280px`；章节头文字 ≤52em、导语 ≤34em |
| 圆角 | 按钮/棋子全圆 999px、卡片 16px、小标签 8px、印章 5px |
| 卡片 | 细线分界（`--line`，12% 透明度），不用厚投影； hover 只允许轻微位移与阴影加深 |
| 按钮 | 高 58px 胶囊，图标圆点 + 文字；悬停时榧木色圆从图标处铺开、上浮 2px；按下 scale(0.98)；次要按钮用 .ghost 描边 |
| 布局 | 中文数字章节（壹贰叁……由 `chapterIndex()` 生成）；章节头 = 编号圆点 + 宽字距标签 + 宋体大标题 + 一句导语 |
| 信息密度 | 每章只讲一件事；要点用短语标签（factTags），不写长段落；数据用大数字（statNum），不用形容词 |
| 文案 | 克制、书面、可带棋类隐喻（404："这一手落在了棋盘之外"）；不出现夸张营销词 |

### 1.3 动效语言

- 全站仅三条缓动曲线：`--ease: cubic-bezier(0.22, 0.8, 0.2, 1)`（交互）、`--ease-io: cubic-bezier(0.65, 0, 0.35, 1)`（转场）、`--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1)`（小元素回弹）
- 入场 `rise`（28px 上浮淡入）、区块转场 `circle-in`（圆形自底部升起，滚动驱动）、阅读进度 `clockline`（顶栏下缘的棋钟线）
- 滚动动画用 `animation-timeline: view()` 或 `scroll()`，必须包在 `@supports` 中；不支持的浏览器直接显示最终状态或隐藏装饰性进度线
- 动效优先用纯 CSS 实现；磁性跟随等必须读取指针位置的效果可放入共享增强包，但不引入 JS 动画库，且关闭脚本后功能与内容不受影响

## 2 技术框架与 UI 组件库

### 2.1 决策：保持零框架 SSR，不引入前端框架

**官网继续使用自研 Node 服务端渲染（`server/` → esbuild → `web.cjs`），不引入 React / Preact / Vue / Svelte / Next 等任何客户端框架。**

理由：

1. 规范基线是"无脚本交互"（ADR-0013）：框架的运行时与这一基线根本冲突。
2. 官网职能是文书 + 下载 + 帮助，服务端直出 HTML 已覆盖全部需求；按 UA 推荐平台、`?start` 自动下载均在服务端完成。
3. 安全约束：构建白名单隔离账号/数据库/联机模块，生产进程无数据库与密钥权限；依赖面越小，审计（SEC-060/061）越简单。
4. 性能与可达性：零脚本页面在任何设备、任何网络下可用，SEO 天然完整。

### 2.2 UI 组件库：项目内自建，不安装外部组件库

**组件 = 纯函数，输入数据、输出 HTML 字符串**（`server/webUi.ts`）。外部 UI 库（MUI、Ant Design、shadcn 等）都依赖客户端运行时，与本架构不兼容，一律不引入。

组件写法约束：

- 纯函数、无副作用、可在构建期或请求期执行
- 一切动态文本经 `esc()` 转义；禁止内联事件（onclick 等）
- 组件不得依赖客户端脚本才能工作
- 样式集中在 Style 文件，组件内不写内联样式

### 2.3 客户端脚本的唯一通道：渐进增强

官网现有两类可选脚本：全站共享的 `scripts/site-enhance.ts`（磁性按钮、悬停预取）与帮助目录的 `scripts/support-search.ts`（检索）。新增脚本必须同时满足：

1. 同源、外部文件、`defer`，禁止内联脚本与内联事件
2. 无脚本时有原生回退（GET 表单 / 链接 / meta refresh），纯装饰效果则直接不出现
3. 在 `scripts/build-website.mjs` 中构建为独立产物，并在 `server/files.ts` 与 `server/staticSite.ts` 登记资源；不打包进 `web.cjs` 页面依赖
4. 脚本只增强，不承载内容；关闭 JS 后页面功能完整
5. 全站通用能力优先并入 `site-enhance.ts`，页面私有能力才单列脚本；不引入框架或动画库

## 3 目录、模块与组件规则

### 3.1 目录边界

维持 `server/` 平铺 + 命名分层（与构建白名单兼容，不新增目录层级）：

```
server/
  page.ts            # 文档外壳 shell()、平台表与顶栏页脚
  pageStyle.ts       # 共享样式：双色区块、顶栏、按钮、页脚、动效
  webTokens.ts       # 设计 token 单一来源（本规范第 4 章）
  webHtml.ts         # 统一 HTML 转义
  webIcons.ts        # 共享 SVG 图标
  webUi.ts           # 共享 UI 组件（本规范第 3.3 节）
  homePage.ts / homeStyle.ts          # 页面与页面样式配对
  downloadPage.ts / downloadStyle.ts
  supportPage.ts / supportStyle.ts / supportContent.ts
  agreementPage.ts / agreementStyle.ts / agreementText.ts
  notFoundPage.ts / notFoundStyle.ts
  board.ts / geometry.ts / ring.ts    # 棋类装饰组件
  support/           # 帮助正文 Markdown（每题一篇，frontmatter 含 title/category）
  supportSources/    # 分类登记（新增篇目在此登记一次）
  legal/             # 法务文书 Markdown
scripts/
  website.ts         # 官网独立入口
  site-enhance.ts    # 全站共享的可选增强包
  support-search.ts  # 帮助目录的渐进增强检索
  check-website.mjs  # 构建时静态 HTML 验收
```

规则：

- **新增任何 `server/` 网页模块，必须在 `scripts/build-website.mjs` 的白名单 `allowed` 中登记**，否则构建直接失败（这是特性，不是麻烦）。
- 官网模块禁止引入账号、数据库、联机模块；`legalMarkdown.ts` 使用受限 Markdown 渲染器，不引入通用渲染库。

### 3.2 模块边界

| 层 | 文件 | 只准做什么 |
|---|---|---|
| token | webTokens.ts | 定义设计变量，不含组件与页面 |
| 共享样式 | pageStyle.ts | 跨页组件样式、双色区块、动效 |
| 外壳 | page.ts | HTML 文档结构、顶栏页脚、平台逻辑 |
| 共享组件 | webUi.ts | 跨页复用的 HTML 片段函数 |
| 页面 | xxxPage.ts | 本页内容、数据组装、调用组件 |
| 页面样式 | xxxStyle.ts | 只含本页私有样式 |
| 内容 | support/ legal/ | Markdown，不含 HTML 逻辑 |

页面文件超过约 200 行时，优先把可复用片段上提为组件，而不是继续堆在页面里。

### 3.3 组件复用规则

1. 新页面只允许使用 `webUi.ts` + `page.ts` 的组件与外壳。
2. 页面私有组件先写在页面文件内；**出现第二次复用时必须上提 `webUi.ts`**，样式同步上提 `pageStyle.ts`。
3. 组件命名 = 功能名小驼峰（`secHead`、`factTags`、`statNum`）；类名沿用现有短横线风格（`.sec-head`、`.btn`、`.ghost`）。
4. 禁止复制粘贴改样式造"差不多"的组件；需要新形态时先改规范。

## 4 样式系统

### 4.1 设计 token（已落地：`server/webTokens.ts`）

token 分八组：colors / fonts / type / leading / tracking / space / radius / motion（另有 zIndex、stones）。
`rootVars()` 输出 `:root` 变量，`pageStyle.ts` 注入全站；**页面与组件只允许引用变量，禁止野生数值**。
修改既有 token 数值 = 全站视觉变更，需单独评审；新增 token 向后兼容。

### 4.2 主题规则：双色区块，不是明暗开关

- `.ink` 与 `.shell` 各自定义 `--bg / --fg / --dim / --faint / --line / --accent / --on-accent`，组件只引用这组语义变量，自动适配所在区块。
- 新增组件**不得硬编码前景/背景色**，必须用区块语义变量，保证同一组件放进两种区块都正确。
- `:root` 的 `color-scheme` 与区块级 `color-scheme` 保持一致，表单控件随之适配。
- 游戏内另有浅色/深色主题设置，与官网无关；官网不做主题切换器。

### 4.3 多语言规范

- 官网当前为中文（`lang="zh-CN"`）；游戏内的文言/中文/English 三语不直接套用到官网。
- 若未来官网增加语言：语言版本在**服务端渲染**（独立 URL 或内容协商），不引入客户端 i18n 运行时；宋体标题仅用于中文，西文标题回退到系统衬线；字距类 token（0.42em 等）仅用于中文标签，西文标签降至 0.12em。
- 数字、版本号、SHA-256、命令一律等宽并保持 LTR。

### 4.4 动效与可达性检查单（每个页面过一遍）

- [ ] 无脚本时内容完整可读、链接与表单可用
- [ ] `prefers-reduced-motion` 下无动画（pageStyle 已统一关闭，新增动画须纳入同一媒体查询）
- [ ] 滚动动画按用途包在 `@supports (animation-timeline: view())` 或 `@supports (animation-timeline: scroll())` 内
- [ ] 有"跳至正文"；`:focus-visible` 用榧木金描边
- [ ] 装饰性图形 `aria-hidden="true"`；图标按钮有可读名称
- [ ] 指针增强只在 `(pointer: fine)` 下启用，不阻塞点击、不改动键盘焦点、不造成布局抖动

- [x] 微交互第一批：棋钟线、落子回弹、磁性按钮、悬停预取（详见第 6 章）

四个阶段均已落地：

1. **阶段一：新页面先行**。任何新页面只准用本规范的组件与 token。
2. **阶段二：旧页面归并（已完成）**。`homePage / downloadPage / supportPage / agreementPage / notFoundPage` 的章节头、按钮、标签、文书页首、目录行与正文目录均使用共享组件；41 个常规页面及 404 回退全部覆盖。
3. **阶段三：样式收编（已完成）**。跨页样式上提 `pageStyle.ts`，帮助页与 404 分别使用 `supportStyle.ts`、`notFoundStyle.ts`；页面样式文件只保留私有部分。
4. **阶段四：验收固化（已落地）**。`npm run build:website` 先检查构建依赖白名单，再由 `scripts/check-website.mjs` 检查全部静态 HTML：禁止内联事件与非白名单脚本，脚本必须外部、同源、`defer`；同时检查重复 ID、失效页内锚点、图片 `alt` 与新窗口链接隔离。失败时中止打包。视觉目检、无脚本与 reduced-motion 仍属于页面变更的发布验收，不以静态检查代替。

## 6 微交互库

微交互服务于"落子、行棋、读秒"的棋类语言，不做与内容无关的炫技。每项都必须注明实现方式与无脚本回退；共享效果只实现一次，禁止各页面复制不同版本。

### 6.1 第一批（已落地）

| 效果 | 棋类化转译与规则 | 实现 | 无脚本 / 不支持时 |
|---|---|---|---|
| 棋钟线 | 顶栏下缘 2px 榧木金细线随全页滚动推进，像棋钟记录对局进程；只表达阅读进度，不抢占注意力 | 纯 CSS：`clockline` + `animation-timeline: scroll(root)`，位于 `pageStyle.ts` | 不显示进度线，正文与导航不受影响；reduced-motion 下关闭 |
| 落子回弹 | 按钮悬停上浮、按下收子、释放轻弹归位；回弹只用于小元素，不用于大区块 | 纯 CSS：`--ease-spring`，`.btn` 的 `transform` / `translate` 过渡 | 保留普通悬停与按下反馈，无功能损失 |
| 磁性按钮 | 指针靠近时按钮像被棋子轻轻吸住；横向跟随 16%、限幅 ±6px，纵向 30%、限幅 ±4px；离开后交给 CSS 回弹 | `site-enhance.ts`；仅精确指针且非 reduced-motion 时启用，使用独立 `translate` 避免覆盖既有 `transform` | 普通按钮与原有 CSS 悬停完整可用；触屏不启用 |
| 手机折叠导航 | 小屏顶栏以 44px 圆形三线按钮展开贝色面板，按钮变为叉号；链接沿细分割线纵向排列 | 原生 `details` / `summary` + CSS；`site-enhance.ts` 补充 Escape、点击外部、选择链接与切换到桌面后的收起 | 无脚本仍可展开、关闭和跳转；桌面导航保持原样 |
| 悬停预取 | 同源导航链接停留 65ms 后预取目标文档，让下一次"行棋"更从容；每个地址只预取一次 | `site-enhance.ts` 动态创建 `<link rel="prefetch">`；仅精确指针且非 Save-Data 时启用，指针离开即取消待执行预取；排除下载文件、资源文件与同页链接 | 按普通链接跳转，内容与下载流程不变 |

### 6.2 交互约束

- 动画不承载唯一信息：章节名、链接、状态与操作结果必须在静态 HTML 中已经成立。
- 不引入滚动劫持、自定义鼠标、持续漂浮、强制视差或自动播放声音；不用动效延迟用户操作。
- 位移只作用于合成属性（`transform` / `translate` / `opacity`），避免改变文档布局；磁性限幅保持小幅，不让目标逃离指针。
- 新增脚本先证明"纯 CSS 做不到"，再进入共享增强包；所有脚本仍遵守第 2.3 节的加载、登记与回退要求。

### 6.3 二期候选（仅记录，尚未落地）

| 候选 | 转译方向 | 落地前提 |
|---|---|---|
| 棋谱收集成就 | 把浏览里程碑转译为"打谱"收集，而非游戏化积分弹窗 | 先确认是否确有价值；本地状态需透明、可清除，不追踪用户 |
| 章节名逐字落子切换 | 不用无意义乱码；当前章节名以逐字落子或棋子翻面方式切换 | 服务端保留完整章节名；用 IntersectionObserver 增强，关闭脚本仍可直接导航 |
| 页脚残局彩蛋 | 页脚小棋盘呈现一局残局，hover / focus 显示一手提示 | 保持装饰定位，不阻挡页脚链接；无脚本时显示静态棋谱 |

二期候选不因"好看"直接开发，须在对应页面迭代中单独确认内容价值、可达性与性能预算。
