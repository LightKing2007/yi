# 弈 · 数据与存储规范

| 项目 | 内容 |
|---|---|
| 所属 | 弈 · 工程规范（YI-STD-001），总则见 [00-general.md](00-general.md) |
| 文件版本 | 1.1.2 |
| 修订日期 | 2026-10-05 |
| 规则前缀 | `DAT` |

参考：ISO/IEC 9075（SQL）；GB/T 35273—2020 第 5 章至第 6 章（个人信息的收集、存储、使用）；ISO/IEC 29100:2011；ISO 22301:2019；GB/T 7408.1—2023 / ISO 8601-1:2019。

## 1 存储介质与选型

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DAT-001 | C | 服务端持久化统一使用 `node:sqlite`（SQLite 3.37 或更高），单文件数据库；严禁同时维护两套持久化格式超过一个版本周期。迁移期间 JSON 存档只读，作为导入来源 | 不适用（阶段 5 实施） |
| DAT-002 | A | 打开数据库后必须立即执行：`PRAGMA journal_mode=WAL`、`PRAGMA foreign_keys=ON`、`PRAGMA busy_timeout=3000`、`PRAGMA synchronous=NORMAL`；启动时必须校验 `PRAGMA integrity_check` 结果为 `ok`，否则拒绝启动 | 不适用 |

## 2 命名

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DAT-010 | A | 表名统一为复数 snake_case 英文名词：`users`、`games`、`rating_changes` | 草案满足 |
| DAT-011 | A | 列名统一为 snake_case；主键统一为 `id INTEGER PRIMARY KEY`；外键统一为 `被引用表单数_id`，如 `user_id`、`game_id` | 草案满足 |
| DAT-012 | A | 时间列统一以 `_at` 结尾，类型为 `INTEGER`，值为 UTC 的 Unix 毫秒数；时长列统一以单位结尾：`_ms`、`_secs` | 草案未满足（以秒为单位） |
| DAT-013 | A | 布尔列统一以 `is_`、`has_` 开头，类型为 `INTEGER`，必须带 `CHECK (列 IN (0, 1))` | 草案未满足（`email_ok`） |
| DAT-014 | A | 严禁以 ISO/IEC 9075 及 SQLite 的保留字作为表名或列名，包括但不限于 `before`、`after`、`at`、`key`、`value`、`order`、`group`、`user`、`index` | 草案未满足（`before`、`after`、`at`、`key`、`value`） |
| DAT-015 | A | 普通索引统一命名为 `idx_表名_列名[_列名]`，唯一索引统一命名为 `uq_表名_列名[_列名]` | 草案未满足 |
| DAT-016 | A | 枚举列统一为 `TEXT`，取值为 kebab-case 英文，必须带 `CHECK (列 IN (…))` 列出全部取值；严禁用无约束的整数表示枚举 | 草案部分满足（`game_type INTEGER` 无约束） |
| DAT-017 | A | 迁移文件统一命名为 `server/db/migrations/NNNN_描述.sql`，NNNN 为四位连续序号，描述为 snake_case 英文 | 不适用 |
| DAT-018 | A | 一张表的列数 ≤ 30；一行的预计大小 ≤ 64 KB（`record` 等 JSON 列除外，其上限见 DAT-024） | 草案满足 |

## 3 字段类型选型

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DAT-020 | A | 全部表统一声明为 `STRICT` 表 | 草案未满足 |
| DAT-021 | A | 金额类、分数类等需要精确运算的值统一用 `INTEGER`，严禁用 `REAL`；段位分为整数 | 草案满足 |
| DAT-022 | A | 文本列必须声明长度上限：`CHECK (length(列) <= N)`；昵称 N = 64（字节上限，按 16 个字素 × 4 字节），邮箱 N = 254，自由文本 N = 2000 | 草案未满足 |
| DAT-023 | A | 每个非空业务列必须声明 `NOT NULL`；允许为空的列必须在注释中写明空值的含义 | 草案部分满足 |
| DAT-024 | A | JSON 列（如 `games.record`）必须带 `CHECK (json_valid(列))`，JSON 内部必须含 `"v"` 版本字段，单值 ≤ 256 KB | 草案未满足 |
| DAT-025 | A | 严禁在一列中存放分隔符拼接的多个值（第一范式）；多值关系统一建子表，如 `game_flags(game_id, flag)` | 草案未满足（`flags`） |

## 4 约束与索引

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DAT-030 | A | 每个外键必须声明删除策略 `ON DELETE RESTRICT`、`CASCADE` 或 `SET NULL` 之一；用户、对局等审计相关数据统一 `RESTRICT` | 草案未满足 |
| DAT-031 | A | 每个外键列必须有以该列开头的索引 | 草案部分满足 |
| DAT-032 | C | 每条在服务端热路径（每条消息或每局都执行）上的查询，必须在 PR 中附上 `EXPLAIN QUERY PLAN` 结果，严禁出现对 1000 行以上的表的 `SCAN`（全表扫描） | 不适用 |
| DAT-033 | C | 复合索引的列顺序统一为：等值条件列在前，范围条件与排序列在后；单表索引数 ≤ 6 | 不适用 |
| DAT-034 | A | 唯一性业务规则（如会员昵称唯一、同一局只能举报一次）必须以唯一索引实现，严禁只在应用层检查 | 草案满足 |

## 5 事务、迁移与访问

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DAT-040 | A | 同一业务动作涉及的多条写入必须在一个事务内完成。对局结束时“写入对局记录、更新双方段位、写入段位变化明细”三项必须在同一事务中 | 不适用 |
| DAT-041 | A | 迁移只允许向前执行，必须幂等，并以 `meta` 表中的 `schema_version` 判断是否已执行；每个迁移在单个事务内执行 | 不适用 |
| DAT-042 | A | 执行迁移前必须自动备份数据库文件到 `/var/lib/yi/backup/pre-migrate-版本号-时间.db`；迁移失败时必须回滚事务并拒绝启动 | 不适用 |
| DAT-043 | A | 严禁删除列或修改列类型的一步式迁移；统一采用“新增列 → 双写 → 回填 → 切换读取 → 下一个版本删除旧列”的扩展收缩模式 | 不适用 |
| DAT-044 | A | 数据访问统一集中在 `server/db/` 下的仓储模块，业务模块严禁直接编写 SQL | 不适用 |
| DAT-045 | A | 所有 SQL 统一使用预编译语句与参数绑定（COD-068） | 不适用 |

## 6 数据分级、敏感数据加密与脱敏

6.1 数据统一分为四级，每一个字段在设计时必须确定其等级：

| 等级 | 名称 | 范围 | 示例 |
|---|---|---|---|
| L1 | 公开 | 其他玩家可见 | 昵称、段位、对局结果 |
| L2 | 内部 | 仅服务端与管理员可见 | 棋谱、对局时间、匿名身份散列 `uid_hash` |
| L3 | 敏感 | GB/T 35273—2020 所称个人信息 | IP 地址、邮箱 |
| L4 | 机密 | 泄露即可冒用身份或控制系统 | 口令、会话令牌、重连令牌、邮箱验证码、管理令牌、私钥 |

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DAT-070 | A | L4 数据严禁以可还原形式存储：令牌与验证码统一只存 SHA-256 散列；口令统一以 scrypt 存储，参数 N = 2^17、r = 8、p = 1，盐 ≥ 16 字节随机，格式为 `scrypt$N$r$p$盐$散列` | 部分满足（重连令牌明文保存在内存） |
| DAT-071 | A | IP 地址（L3）入库前必须截断：IPv4 保留前 24 位，IPv6 保留前 48 位；需要识别同一来源时，统一存 HMAC-SHA-256（密钥每 90 日轮换）。草案中 `black_ip`、`white_ip` 必须改为截断形式 | 草案未满足 |
| DAT-072 | A | 邮箱（L3）统一以小写形式存储，并对本地部分做 Unicode NFC 规范化；严禁在日志、错误消息、管理工具的列表输出中显示完整邮箱，统一脱敏为首字符加 `***@域名`（如 `l***@example.com`） | 不适用 |
| DAT-073 | A | 日志与审计记录中严禁出现 L4 数据；L3 数据必须按 DAT-071、DAT-072 脱敏后才允许写入 | 满足（日志不含 IP 与令牌） |
| DAT-074 | A | L3 数据保留期 ≤ 180 日，到期由定时任务清空或截断；L2 棋谱保留期为永久，玩家申请删除账号时必须在 15 日内完成匿名化 | 不适用 |
| DAT-075 | A | 匿名身份 `uid` 只允许以 `sha256('yi:' + uid)` 的前 32 位十六进制形式在服务端出现，严禁存储或记录原值 | 满足 |
| DAT-076 | C | 新增 L3 及以上字段，必须在 PR 中写明收集目的、保留期和脱敏方式，并更新隐私说明 | 满足 |

## 7 客户端本地存储

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DAT-080 | A | 本地存储的每个 JSON 值必须含版本字段 `v`；读取时必须逐字段校验类型与取值范围，校验失败的字段回退为默认值，严禁把未校验的值合并进运行状态 | 未满足（`settings.ts` 浅合并） |
| DAT-081 | A | 本地存储整体解析失败时，必须把原值改存到 `键名.corrupt` 后再使用默认值，并写一条 `warn` 日志；严禁静默丢弃原值 | 未满足 |
| DAT-082 | A | 本地存储的读写必须包在 `try` 中（隐私模式、配额已满时会抛出异常）；写入失败不得影响游戏运行 | 满足 |
| DAT-083 | A | 本地存储的值 ≤ 64 KB；严禁在本地存储中保存 L4 数据（3.0 的登录令牌统一由 Electron `safeStorage` 加密后存放在主进程） | 满足 |

## 8 存档写入与备份

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DAT-050 | A | 存档文件“不存在”与“存在但无法解析”必须区别处理：前者视为首次运行；后者严禁启动，必须保留原文件不动，写 `error` 日志，并以退出码 65（数据格式错误）退出 | 未满足（F-01） |
| DAT-051 | A | 写盘统一采用“写临时文件 → `fsync` 临时文件 → 原子改名 → `fsync` 目录”四步 | 部分满足（缺两次 `fsync`） |
| DAT-052 | A | 写盘失败时，必须保留内存中的数据，按 1 秒、2 秒、4 秒……的间隔重试，间隔上限 60 秒；连续失败 3 次时写 `error` 日志；严禁因写盘失败使进程退出 | 未满足（F-23） |
| DAT-053 | A | 进程收到 `SIGTERM` 或 `SIGINT` 时，必须在退出前完成最后一次写盘；写盘失败时，必须把数据转储到 `/var/lib/yi/emergency-时间.json` | 部分满足 |
| DAT-054 | A | 每次写盘前，必须把上一版存档复制为 `文件名.prev`，保证任何时刻都存在一份完整的上一版本 | 未满足 |
| DAT-060 | A | 生产数据的恢复点目标 RPO ≤ 24 小时，恢复时间目标 RTO ≤ 1 小时（阶段 5 引入数据库后，RPO 缩短为 ≤ 1 小时） | 满足（每日本地备份与异地备份使 RPO ≤ 24 小时；2026-10-05 恢复演练中下载、解密与校验约 2 分钟，服务器上的替换步骤估计不超过 10 分钟，见 [audits/2026-10-05-restore-drill.md](../audits/2026-10-05-restore-drill.md)） |
| DAT-061 | A | 备份按 3-2-1 原则：至少 3 份副本、2 种介质、1 份异地。第一层为服务器本地 `/var/lib/yi/backup/` 每日一份，保留 7 份；第二层为异地对象存储每日一份，保留 30 份日备与 12 份月备 | 满足（P0-02 本地每日一份、保留 7 份；P1-13，#82：异地为阿里云 OSS 华东1（杭州），与服务器所在的成都不同地域，`daily/` 与 `monthly/` 由存储桶的生命周期规则分别保留 30 日与 365 日；2026-10-05 安装） |
| DAT-062 | A | 数据库备份统一使用 SQLite 的在线备份接口（`VACUUM INTO` 或 backup API），严禁直接复制正在写入的数据库文件 | 不适用 |
| DAT-063 | A | 异地备份必须先用 age 或 GPG 加密，私钥严禁存放在服务器上 | 满足（P1-13，#82：以 age 加密后上传，私钥只在项目所有者本机；OSS 的访问密钥只有两个前缀的 PutObject 权限） |
| DAT-064 | A | 每个备份文件必须同时保存 SHA-256 校验和；备份任务失败必须写 `error` 日志，并在当日运维检查中处理 | 满足（`scripts/server/backup.sh` 为每份写 `.sha256`，失败写 error 级别日志；异地备份上传前核对 `.sha256`，上传时以 Content-MD5 与 ETag 核对；每日检查见 [ops.md](../procedures/ops.md) 第 2 章） |
| DAT-065 | D | 每季度必须演练一次恢复：从异地备份恢复到临时目录，校验条数与校验和，并把结果记入 `docs/audits/` | 满足（2026-10-05 首次演练通过，见 [audits/2026-10-05-restore-drill.md](../audits/2026-10-05-restore-drill.md)；下一次在 2027 年第 1 季度） |
| DAT-066 | A | 执行任何会修改生产数据的手工操作前，必须先手工备份一次 | 满足（未成文） |
