## 2 文档要求

| 编号 | 等级 | 规定 | 现状 |
|---|---|---|---|
| DOC-001 | A | 规范类与计划类文档必须以文档信息表开头，统一包括：文件版本、修订日期、状态、相关文档 | 部分满足 |
| DOC-002 | A | 文档统一按 [09-text-and-i18n.md](09-text-and-i18n.md) 书写；章节统一以阿拉伯数字编号，层级 ≤ 4 级 | 部分满足 |
| DOC-003 | A | 改变行为、接口、配置、流程的 PR，必须在同一 PR 中更新受影响的文档；PR 检查清单中逐项确认 | 满足 |
| DOC-004 | A | 文档中的相对链接必须有效，由 CI 检查 | 未满足（未检查） |
| DOC-005 | D | 每季度复审一次全部文档，过时内容必须更新或删除，复审结果记入审计报告 | 未满足 |
| DOC-010 | A | 代码中的规则实现（测试、钩子、工作流步骤）必须在注释中标注所实现的规则编号，如 `// 实现 API-043` | 未满足 |
| DOC-020 | C | 缺陷与待办统一记录在 GitHub Issues。标签分为：`bug`、`feature`、`security`、`incident`、`standards`、`p0`、`p1`、`p2`；每个 Issue 必须有且只有一个优先级标签 | 未满足 |
